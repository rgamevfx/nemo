# AGENTS.md

Context for AI agents (and humans) working in this repository. The product
specification is `docs/composition_network_vfx_nle_spec_v2.md` — read the
sections relevant to your task. Architecture decisions live in
`docs/decisions/` (ADRs); do not contradict them without updating them.

## What this project is

A unified VFX compositor and NLE: node-based compositing (Nuke-like
interaction), conventional timeline editing, color, and delivery, in one
procedural network model. C++20 core, Vulkan + Slang rendering, Qt 6 Quick UI,
Windows and native Linux Wayland as first-class targets.

## Module boundaries (spec section 10.2 — mandatory)

| Module | Owns | Hard boundary rule |
| --- | --- | --- |
| `src/nemo/core` (Document) | IDs, sources, sequences, network definitions/instances, parameters, versioned serialization | No Qt, Vulkan, or plugin-runtime objects in the persistent model. |
| Commands | Validated edits, transactions, undo/redo | UI, scripts, and agent adapters mutate ONLY through the command API. |
| Evaluation | Dependency plans, time mapping, scheduling, invalidation, cache policy | Headless-capable; never depends on panel selection or layout. |
| GPU | Allocations, kernels, submission, synchronization | Explicit resource lifetimes and completion rules; no routine CPU readback. |
| Media | Decode/encode, image I/O | Converts external formats to the application media contract. |
| Presentation | Panels, input, view models | Reads model state, submits commands, never mutates render state directly. |
| Automation | Python/CLI/MCP adapters | No adapter dependency inside core evaluation. |

Cross-module access to internal data structures, mutable global state, and
service locators are prohibited (spec section 10.2).

## Commands

One dependency-manager path: **vcpkg manifest mode** (pinned baseline in
`vcpkg.json`) for pure-C++ deps; system packages for Qt6/Vulkan/FFmpeg
(ADR-0002). `VCPKG_ROOT` must point at a vcpkg checkout. Machine-specific
overrides go in `CMakeUserPresets.json` (gitignored) — copy
`CMakeUserPresets.json.example`.

```bash
# Configure (first run bootstraps the manifest deps; needs ninja + VCPKG_ROOT)
cmake --preset debug
# Build
cmake --build --preset debug
# Test
ctest --preset debug
# Sanitizers
cmake --preset asan && cmake --build --preset asan && ctest --preset asan   # ASan+UBSan
cmake --preset tsan && cmake --build --preset tsan && ctest --preset tsan   # TSan
# Release
cmake --preset release && cmake --build --preset release

# Format (CI enforces)
clang-format -i <changed .cpp/.hpp files>
# Static analysis (opt-in locally, required for new modules)
cmake --preset debug -D NEMO_ENABLE_CLANG_TIDY=ON
```

Headless verification without any UI (agents: use this instead of launching
the app):

```bash
build/debug/apps/nemo-cli/nemo-cli validate <project.json>   # JSON diagnostics on stdout
build/debug/apps/nemo-cli/nemo-cli render <project.json> --out frame.ppm --frame 12
```

`render` output is deterministic; use it for image assertions. Treat
pixel-diff expectations generated by an agent as evidence, not oracle —
humans inspect image differences.

## Coding rules

- C++20. RAII and explicit ownership; no raw `new`/`delete` outside
  container implementations. `[[nodiscard]]` on pure queries.
- Errors that identify the offending relationship (e.g. cycles, occupied
  ports) — never bare failure codes.
- Every mutation of the Document goes through a `Command` so undo/redo and
  scripting behave identically.
- Evaluation/caching: results carry revision + request identity; stale work
  never overwrites newer results (spec section 10.2).
- Time semantics per spec section 4.3: move/trim/slip/retime each touch only
  their own layer of the mapping.
- Threading: document the contract of anything shared across threads;
  bounded queues; no blocking the UI event thread.

## Definition of done (for a PR)

1. Builds clean in `debug` and `release` with `-Wall -Wextra -Wpedantic`
   (warnings are errors in sanitizer presets).
2. Relevant tests added/updated and green: `ctest --preset debug`; sanitizer
   preset green for anything touching ownership/concurrency.
3. Commands identical locally and in CI — if you cannot run the checks, say
   so explicitly in the PR.
4. No new dependency without a pinned manifest entry + human review.
5. No public API change, no changed image baseline, no new node type without
   explicit human review in the PR description.
6. Spec conformance checked for touched behavior; ADR added for any
   architectural decision.

## Working conventions

- One issue per branch. Branch names `issue/<n>-short-slug`.
- Issues specify: outcome, scope, non-goals, acceptance examples, verification
  commands. PRs report: what changed, test evidence, limitations, and image
  diffs where relevant.
- Keep ticket status and decisions in GitHub/docs, never in chat history.
