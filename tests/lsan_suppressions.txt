# LeakSanitizer suppressions for the Vulkan stack (issue #2 GPU bootstrap).
# The Vulkan loader and dlopen'd ICD drivers allocate through libdbus and
# keep working allocations alive until process exit; those leaks sit inside
# third-party code, not nemo's RAII-owned resources. Keep this list narrow:
# each entry must name third-party machinery, never a nemo frame.
leak:libdbus-1.so.3

# Issue #10 hardware media probe/encode: engine-internal allocations made
# during codec init-verification stay alive until process exit inside
# third-party libraries, not nemo-owned RAII resources.
# - system libx265 leaks its per-encoder-open internal allocation by
#   design (encoder open/close through libavcodec does not free it).
# - the CUDA driver (libcuda) keeps cuInit/lifetime context allocations
#   alive until process exit (documented CUDA behavior; NVENC probing).
# - the glibc/ffmpeg loader keeps per-thread key allocations alive.
leak:libx265
leak:libcuda.so
leak:libavutil.so.58
# Probe/decode init threads: allocations inside dlopen'd NVIDIA/x265
# engine code surface with an <unknown module> frame; the only nameable
# frame is glibc's pthread_cond_broadcast (thread-key machinery that
# stays alive until exit). Function-level is the narrowest match
# available — no nemo allocation stack passes through it.
leak:pthread_cond_broadcast
