## What changed

Seven units replace everything between the graph panel's read-only snapshot and
the pointer. All of them live in `apps/nemo-ui`, in `namespace nemo::ui`, and
the architectural record is `docs/decisions/0009-graph-interaction-core.md`:

| unit | files | responsibility |
|---|---|---|
| scene | `GraphScene.hpp/.cpp` | `buildGraphScene` projects one snapshot into immutable records with an identity index; the caller stamps `revision` |
| geometry | `GraphGeometry.hpp/.cpp` | the single owner of card rectangle, port position, affordance box, side guard, route polyline and point-to-segment projection, plus `GraphViewTransform` |
| hit test | `GraphHitTest.hpp/.cpp` | `hitTestGraph` — one ordered pass resolving affordance, port (per direction), connection endpoint, reroute dot, card and pipe body, plus the published `GraphHover` |
| gestures | `GraphSessions.hpp/.cpp` | `GraphSession` (begin/update/cancel/commit) with `MoveSession`, `ToggleSession`, `MarqueeSession`, `ConnectSession`, `RerouteSession`, `ScopeEnterSession`, `ViewSession` |
| command facade | `GraphCommandFacade.hpp/.cpp` | the one place in the interaction layer that calls the graph command API |
| painter | `GraphItem.hpp/.cpp` | consumes the scene, the geometry and the active session's `GraphPreview`; computes no layout and holds no interaction state |
| panel | `qml/GraphPanel.qml` | input plumbing, chrome, popups, shortcuts, panel-state records; no geometry, no element iteration, no pick |

`GraphInteraction` (QML element `GraphInteraction`, `objectName: graphInteraction`)
is the only object the panel and the paint item talk to: it owns the scene, the
view transform, the selection, the hover result and the active session.

Outside the interaction layer the change is three lines plus one presenter
accessor:

- `ViewerController::graphRevision()` is the document revision a graph snapshot
  is projected from. The interaction stamps its scene with it and aborts a live
  gesture when it changes, so a gesture never rebases against a superseded
  snapshot. It is a separate query rather than a field inside
  `graphSnapshot()`'s map, precisely so the projection's content stays what it
  was — an earlier draft put the revision in the map and broke
  `Interactive.GraphScopeEditsDoNotFallBackToRoot`, whose premise is that a
  child-scope edit leaves the root snapshot alone.
- `GraphItem::labelAtlasesRasterized` and `GraphInteraction::hitTestPasses` are
  the two cost diagnostics the count assertions read.
- `apps/nemo-ui/qml/GraphPanel.qml~`, the tracked editor backup the ticket names
  as dead weight, is deleted.

## Production correctness

Six defects were found and fixed during integration, five of them by the tests
and one by review. Each is recorded because each one is a behaviour the artist
would have felt:

1. **A wheel burst applied once per burst, not once per turn.** `queueZoom`
   gated the per-turn timer on the burst-dirty flag, which only the settle timer
   clears, so every notch after the first accumulated with no timer running and
   landed late. Gated on the turn flag, which the turn timer clears — the
   replaced panel's own `zoomQueued` model. Caught by
   `GraphWheelBurstAppliesPerTurnAndPersistsOnceWhenItSettles`.
2. **Alt on a pipe pulled a wire instead of inserting a reroute dot.** The
   `PipeBody` branch had lost the replaced handler's `alt && pipe` case. Caught
   by the reroute assertions in
   `GraphScreenSpaceHitTestingSurvivesEveryZoomLevel`.
3. **Scope entry ignored where the pointer was released.** The session reported
   its node unconditionally; the release now checks the affordance it landed on
   with its own ordered pass, so pressing an affordance and releasing elsewhere
   does nothing at all. Caught while reviewing the release path.
4. **The pulled pipe fixed the wrong end.** A plain body drag fixes the
   destination and moves the source (Shift does the reverse); the dispatch fixed
   the source. `preferOutputEndpoint` was inverted with it, so the ring marked
   the wrong end too. Caught by `GraphPipePullLocksSourceOrDestinationOnPress`.
5. **`GraphInteraction::nodeRect`/`portPosition` reported authored positions
   during a gesture.** A held drag changed nothing the caller could see, where
   the replaced paint item reported the card on screen. They now include the
   active session's transient offset — the same offset the painter applies.
   Caught by
   `HistorySurface.UndoCancelsGraphAndParameterPreviewAndReleaseCannotCommit`.
6. **A release did not notify the last-click record.** `lastClickValid`,
   `lastClickX` and `lastClickY` notify `viewChanged`, and the release set them
   without emitting; the panel's binding stayed stale, so the click's own
   panel-state write recorded `lastClickValid: false` and the next read of the
   record wiped the placement point. Found by tracing the failing assertion —
   `GraphScreenSpaceHitTestingSurvivesEveryZoomLevel` depends on it.

One defect was found by the owner after this work landed, and is fixed on top of
it: **a dragged card's pipes stayed at the authored position until release.**
The rewrite replaced the panel's per-move republication of node positions with
transient offsets applied at paint time, and the painter applied them to cards,
ports and labels but not to the edge walk, which read `routePolyline` from the
scene's authored positions — and culled on them. The replaced panel had baked
`dragDeltaX/Y` into the node list on every move, which is why its painter's
endpoints followed. The edge walk now displaces the polyline's two endpoints by
the two ends' own transient offsets before bounds and drawing, so the reroute
candidate and the cull follow with them; the enter affordance record applies the
same offset, and `previewChanged` notifies `affordancesChanged`, without which a
dragged subnet's chip would have stayed stale anyway. Verified by a mid-drag
native capture — the dragged card's displayed output port carries the pipe and
the authored position carries only background — and by the chip's record moving
by exactly the drag delta.

Two more were caught by review before they could matter: `ConnectSession`
measured its move threshold from the fixed port rather than the press (a plain
click on a wire would have disconnected it), and `acceptsWheel()` refused the
wheel during a *pending* pipe pull, where the replaced panel only refused it
during an active wire drag.

Also fixed while reviewing: `RerouteSession` re-published its candidate by
copying the whole route vector on every pointer move. The candidate is now the
single buffer the preview owns, written in place, which is what `MoveSession`
already did for its transient positions.

Two conformance notes where the rewrite deliberately differs from the replaced
code, both stated so a reviewer can judge them:

- **Route and position parsing is stricter.** The replaced `pointFromVariant`
  accepted any `QVariantList`, and Qt converts a string into one `QVariant` per
  character, so a junk route entry silently became a point at the origin and
  moved the content bounds. The projection now accepts the three documented
  shapes and skips anything else. No producer emits the malformed shape, so no
  accepted composition changes; a malformed one can no longer shift the scene.
- **The paint item's size is the content bounds plus its margin**, not the
  replaced item's fixed 2600×1500. The item's bounds were never used for
  clipping or input (culling is the view rectangle), so nothing observable
  changes, and the fixed pair was the kind of hard-coded stand-in the repository
  forbids.

### Structural cost: what a frame rebuilds

The review of this branch found two costs by reading the code — allocator
traffic in the pick path, and a whole-scene geometry rebuild per frame. Both are
settled as counts by `WorkspaceDragTest.GraphFrameCostFollowsWhatMoves` (sixty
cards, no pipes, one card dragged):

| cost | budget | observed |
|---|---|---|
| static geometry rebuilds during a drag | two: one when the dragged card leaves the static group, one when the release puts it back | two, and none for the six moves between them |
| vertices built per drag step | one card's worth, not the network's | under 1000 — a card is 48 body + 96 border + 132 per port — against a static group of 16,560 |
| label rasterisations during a drag | zero | zero |
| hit-test passes per pointer move | exactly one | one |

The pick path allocates nothing: `routePolyline` fills a caller-owned buffer and
the ordered pass reuses one set of buffers (`GraphHitScratch`) across edges and
across pointer moves, so a hover in a thousand-edge network asks the allocator
for nothing. The card outline is a constant shape derived once and translated
per card, instead of a trigonometric pair per outline point per card per frame.

The frame split is verified against Qt's own batcher, not only against our
counters: on the same run with `QSG_RENDERER_DEBUG=render,upload`, the static
batch (`Nodes: 2`, 16,560 vertices) reports `[retained]` on every drag frame
while 462 vertices upload — the moved card and the port overlay — and it uploads
exactly twice, when the drag takes the card out of the group and when the
release puts it back. The separation is structural, not incidental: Qt
re-uploads a whole batch when any of its geometry is dirty and merges only
within one batch root and clip list, and an identity transform node is not a
batch root until Qt promotes one, so the static group is bracketed by clip nodes
whose rectangles are the item's bounds plus a slack no drawn shape reaches.

## Review resolutions

The change was reviewed on two axes (repository standards and the ticket spec)
before landing. The accepted findings, all fixed in the same commit:

| finding | resolution |
|---|---|
| A right press during a live gesture also opened the node context menu, where the replaced panel only cancelled | The menu is offered only when no gesture was running when the press arrived; a right press mid-drag or mid-pull only cancels. Artist-visible conformance fix, caught by the spec axis. |
| A wire pull resolved a second pick per pointer move (`ConnectSession` re-ran `hitTestGraph` after the interaction's hover pass), so the cost budget's one-pass claim held only for gestures that do not hit-test | `GraphSessionContext` now carries the event's own ordered pass, and every session reads the element it needs from it: `MoveSession`'s drop target, `ConnectSession`'s destination and card, `RerouteSession`'s hit. ## Limitations and open items

- **Slice 7 is not implemented** — see the conformance table. No approved
  feedback slice is in this change, and no commit here mixes conformance with
  new design.
- **Owner review of prototype feel and visual parity is the outstanding gate.**
  This change reproduces the accepted behaviour and the accepted gesture
  vocabulary; it does not claim the owner's acceptance. The native captures
  under `docs/evidence/assets/issue100-graph-interaction-core/` are the material
  for that review.
- **Wall-clock performance is not measured here.** The ticket bounds gesture
  cost as counts, and the measured gate stays with its existing owner.
- **Two paint-order cases inside overlapping cards move with the frame split.**
  A card being dragged, and the accent a hovered port paints, are drawn in the
  transient group over the static cards rather than at their position in the
  node order, so a card dragged over a card that comes later in the network now
  paints over it, where the replaced painter drew it under. That follows from
  keeping the static group in a batch of its own, which is what makes a drag
  cost the same at sixty nodes or a thousand; preserving the exact interleaving
  would need one static group per gap between moved cards. Recorded for the
  owner's call rather than decided here.
- **The static card group is not culled to the viewport.** Culling it would make
  its vertices a function of the view and rebuild them on every pan and zoom
  step — the cost this work removes. The group is uploaded once and the surface
  clip discards the off-screen pixels, so the trade is a constant per-frame
  vertex count proportional to the network in place of a per-gesture rebuild. If
  a network large enough to make that count matter arrives, the lever is a
  quantised view window in the static key, not a return to per-frame rebuilds.
- **The pre-existing unrelated failing colorimetry test** is untouched.
